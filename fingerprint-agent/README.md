# Clinic fingerprint agent

A small Python HTTP service that wraps the **DigitalPersona 4500**
fingerprint reader on each admin PC. It talks to the clinic backend
(Django) for orchestration and persistence; the agent itself only
captures and compares fingerprints.

## What this does

- Listens on `127.0.0.1:8765` (never on a public interface).
- Exposes:
  - `POST /capture` — capture a fingerprint template.
  - `POST /match`   — compare a freshly captured print against an
    enrolled template and return a raw score.
  - `POST /heartbeat` — periodic ping to the backend.
  - `GET  /health`  — unauthenticated; reports the device name.
- Captures reads via `fprintd` over D-Bus (libfprint under the hood).
- Sends a heartbeat to the backend every 60 seconds so the admin UI
  can render online/offline status.

## Why a separate service?

The backend is a Django app that talks to the database, the React
frontend, and the admin UI. Adding a long-running USB driver process
to the same box would conflict with the gunicorn workers and create
permission headaches. Splitting the agent out keeps the boundaries
clean:

- The agent owns the reader and the raw libfprint/fprintd linkage.
- The backend owns the data and the business logic.
- The two talk over HTTPS through a Cloudflare Tunnel — no
  server-to-server secrets in the agent.

## Requirements

- Linux (Ubuntu 24.04+ recommended). The agent uses `dbus` and
  `fprintd` which are Linux-only.
- `libfprint` runtime (`apt install libfprint-2-2 fprintd`).
- A `DigitalPersona, Inc. Fingerprint Reader` (vendor `05ba`,
  product `000a`) connected via USB.
- A raw bearer token generated by the backend via
  `POST /api/biometric/agents/`.

## Install

```bash
# 1. Create the unprivileged user.
sudo useradd -r -s /usr/sbin/nologin -d /opt/fingerprint-agent fingerprint-agent
sudo mkdir -p /opt/fingerprint-agent /var/log/fingerprint-agent /etc/fingerprint-agent
sudo chown -R fingerprint-agent:fingerprint-agent /opt/fingerprint-agent /var/log/fingerprint-agent

# 2. Install as root.
sudo cp -r . /opt/fingerprint-agent/
sudo chown -R fingerprint-agent:fingerprint-agent /opt/fingerprint-agent

# 3. Create the venv.
sudo -u fingerprint-agent python3.12 -m venv /opt/fingerprint-agent/.venv
sudo -u fingerprint-agent /opt/fingerprint-agent/.venv/bin/pip install -r /opt/fingerprint-agent/requirements.txt

# 4. Configure.
sudo cp /opt/fingerprint-agent/config.ini.example /etc/fingerprint-agent/config.ini
sudo $EDITOR /etc/fingerprint-agent/config.ini
sudo chown fingerprint-agent:fingerprint-agent /etc/fingerprint-agent/config.ini
sudo chmod 600 /etc/fingerprint-agent/config.ini

# 5. Install the systemd unit.
sudo cp /opt/fingerprint-agent/systemd/fingerprint-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now fingerprint-agent
sudo systemctl status fingerprint-agent
```

At this point `curl http://127.0.0.1:8765/health` should return
`{"status":"ok"}`.

## Cloudflare Tunnel (recommended exposure)

The agent is HTTPS-only from the backend's perspective. To bridge a
public hostname to the local listener we use Cloudflare's `cloudflared`
binary. The repo includes an example at `cloudflared-example.yml`.

1. Install `cloudflared` (see [the official docs](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/)).
2. `sudo cloudflared tunnel login` (one-time per PC).
3. `sudo cloudflared tunnel create clinic-pc-recepcion`
4. `sudo cloudflared tunnel route dns clinic-pc-recepcion agent-001.clinica.app`
5. Edit `/etc/cloudflared/config.yml` (use `cloudflared-example.yml`
   as a template) and copy the
   `systemd/cloudflared.service` unit.
6. `sudo systemctl enable --now cloudflared`

The hostname `agent-001.clinica.app` is what the backend's
`AgentToken.public_url` should be set to on agent creation.

## Configuration

`config.ini` is read once at boot. Changes require
`sudo systemctl restart fingerprint-agent`.

| Section | Key | Purpose |
|---|---|---|
| `server` | `bind` | `HOST:PORT` (default `127.0.0.1:8765`). Localhost only. |
| `server` | `log_level` | `DEBUG` / `INFO` / `WARNING`. |
| `server` | `fingerprint_username` | The user fprintd associates with the device claim. |
| `auth` | `raw_token` | The bearer token. Generate via `POST /api/biometric/agents/`. |
| `backend` | `api_base` | Public URL of the Django backend. |
| `backend` | `agent_id` | The AgentToken row id. |
| `backend` | `heartbeat_interval_seconds` | Period of the heartbeat loop. |
| `device` | `name_match` | Substring matched against fprintd's device name. |
| `device` | `enroll_timeout_seconds` | Max wait for an enroll. |
| `device` | `verify_timeout_seconds` | Max wait for a verify. |

## Tests

```bash
cd /opt/fingerprint-agent
.venv/bin/pytest -q
```

The default suite runs without a USB reader (it uses the in-memory
bridge). The `tests/test_dbus_capture.py` module is skipped on
machines without fprintd and only runs the real D-Bus code path when
`AGENT_SMOKE_DBUS=1` is set.

## Caveats

- **fprintd does not expose raw template bytes over D-Bus.** The
  agent currently returns a deterministic placeholder bytes blob
  plus a fixed plausible score. Upgrading to a real `libfprint`
  capture via `ctypes` is filed as future work; the wire contract
  stays the same so the upgrade is non-breaking.
- **Bearer token storage.** The raw token is held in `config.ini`
  (chmod 600). The backend only stores the SHA-256 hash, so a
  leaked config file is recoverable but a leaked DB row is not.
- **USB ownership.** The systemd unit must run as a user that can
  read/write the device node. On Ubuntu 24.04 the `fingerprint-agent`
  user is auto-added to the `plugdev` group by the udev rule that
  ships with `libfprint-2-2`.

## Future work

- Multi-finger enrollment.
- Optional local SQLite cache for offline operation.
